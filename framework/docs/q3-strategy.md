## v6 为什么是最大的一步

拆解旧版的路程构成（`script/q3_time_audit.py`，24 seed）：

| 类别 | 路程 | 占比 |
| --- | --- | --- |
| `measure@refine` | 14653 m | 48.1% |
| `clear@localized` | 7562 m | 24.8% |
| `measure@cover-scan` | 7200 m | 23.7% |

而 `_finish_pending` 原来按 **频道号升序** 处理待清频道——等于让机器狗在 1800m 的圆域里
按频道号随机横跳。**"访问所有源"本身就是一个 TSP**，仅换成在线最近邻，路程就掉 37%。

同族距离下界（覆盖扫描 7200m + 扫描后访问全部源的最优路径 8977m）= **16177m**，
当前实现 17609m，**只差 8.8%** —— 这条策略族的路线已经基本走到头。

## 关键权衡（都用 `script/run_batch.py` 量过）

1. **先全扫再逐个定位**（`localize_before_full_scan=False`）比"边扫边定位"好：
   后者每解决一个频道就要折返扫描点，实测多走约 4km。
2. **路程权重不能太大**：`travel_weight > 1/1000` 会让精定位点为了省路程牺牲角度分离，
   清除率掉到 0.97 左右。默认 `1/1200`。
   注意这是**旧打分**（只有"分离度 − 路程"两项）的结论；v7 给打分补上了
   "离源多近"这一项之后，权重语义已经不同。
3. **扫描半径不是越小越好**：路程随半径单调下降，但覆盖余量随半径下降。
   1125m 已贴着理论下界（余量 0.9m），1200m 余量 31m，1400m 余量 86m。
   **默认 1200m**：1125 只省 2.6%，但"确保全部清除"是硬前提，不值得冒险。
4. **覆盖扫描设计已接近最优**：把"每停点要扫 20 个频道（120s）"算进去之后，
   在正 n 边形巡游族里穷举（`script/q3_cover_design.py`），同余量下最优只比
   当前设计省 17s。**不要在这里继续投入。**
   反例提醒：11 边形 r=870 的路程只要 5772m（vs 7200m），但 12 个停点要多花
   600s 检测时间——**路程最短 ≠ 时间最短**。

## 下一步（按预期收益排序）

1. **逼近段（7005m / 41%）**：把"一步贪心打分"升级为**有 cost-to-go 的序贯决策**。
   状态 = (可行域多边形, 当前位置)，动作 = 下一个检测点，单步代价 = 路程/5 + 6s，
   终止条件 = 包围圆半径 <= 20m。可用小宽度 beam search 近似。
   两点测向的解析最优解是"先沿方位线接近到约 0.3d、再横向约 0.15d"，
   这与现在"在估计点周围 30/60/120/250m 环上按打分挑点"是两套逻辑。
2. **每个停点的 20 频道全扫（840s / 19%）**：现在只跳过"已 <= 20m"的频道，
   可以试更激进的剪枝（需要保守的正确性论证）。
3. **问题4**：定向源覆盖角只有 ±90°，`no_signal` 不再等价于"距离太远"，
   可行域必须加入"不落在覆盖角内"的**非凸**约束；策略需要分支 / 多假设。
4. **正式测试前的复现**：用 `ReplayClient` 把线上演练的 `run.jsonl` 重放，
   确认本地逻辑与线上一致后再跑正式测试；
   线上演练全流程见 `script/run_practice_online.py` 与 [`../说明.md`](../说明.md)。
