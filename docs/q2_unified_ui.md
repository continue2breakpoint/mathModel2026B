# 题目 2 统一编辑台（收纳页 · 辅助线 · 导入导出）

问题 2 原来有两个各自成页的可视化程序：

| 旧页面 | 内容 | 缺什么 |
| --- | --- | --- |
| `/`（`q2_dashboard.py` 内联 HTML） | 双点交会：S1、θ1、ρ → 第二检测点 S2 热图；辅助线齐 | 没有导入 / 导出 / 粘贴 |
| `/matrix`（`q2_matrix_dashboard.html`） | 知识矩阵：Channel × Path 观测表 → 下一观测点热图 | 只有核心热图与可能区域，辅助线几乎没有；观感与前者割裂 |

现在两边合并成**同一个编辑可视化界面**：一套外壳、一套控件、一套配色、一套辅助线绘制器、
一套导入导出面板；两个模型仍然各自保留自己的数学口径（见
[知识矩阵热图](./q2_knowledge_heatmap.md) 与 `q2_dashboard.py` 顶部说明），
切换工作区即可，不需要在两个割裂的页面之间来回跳。

```
python3 script/q2_dashboard.py --port 8055
http://127.0.0.1:8055/           # 默认双点交会工作区
http://127.0.0.1:8055/matrix     # 默认知识矩阵工作区（同一个页面）
```

## 1. 收纳页：编辑台的三态

编辑台（drawer）是把"输入 / 参数 / 辅助线 / 显示 / 探针"全部收进一个可伸缩抽屉的方案，
三态由 `#drawer[data-state]` 驱动，画布始终是主角：

| 状态 | 表现 | 适合 |
| --- | --- | --- |
| `collapsed` 收起 | 只留 48 px 图标栏，画布占满整个宽度 | 看图、截图、对照两张图 |
| `half` 半屏 | 抽屉停靠右侧，约占视口宽度 46%（430–940 px），画布自动重排 | 一边调参一边看图（默认） |
| `full` 全屏 | 编辑页覆盖整个视口，内容限宽 1180 px 居中 | 专心编辑观测表 / 粘贴长 JSON |

交互：

* 顶栏 `收起 / 半屏 / 全屏` 分段按钮，或编辑台右上角 `⇥ ◫ ⛶`；
* 快捷键：`E` 循环三态，`F` 切全屏，`Esc` 全屏→半屏、半屏→收起；
* 收起状态下点左侧图标栏任一图标，会自动展开半屏并跳到对应小节；
* 状态写进 URL：`?ws=matrix&drawer=full` 可直接分享 / 收藏某个视图；
* 画布容器尺寸变化后自动 `Plotly.Plots.resize()`，不会出现"图层被压扁"。

## 2. 一份外壳，两个工作区

顶栏切换工作区，二者共享**全部**外观与交互部件：

| 部件 | 说明 |
| --- | --- |
| 小节（section） | 数据 / 观测（或 S1）/ 模型 / 精度 / 辅助线 / 显示 / 探针，两个工作区同序同位 |
| 控件工厂 | 滑块+数字联动、下拉、复选、按钮、徽章、表格，样式与行为一致 |
| 配色管线 | log / sqrt / linear / 分位（rank）四种映射、2%–98% 分位裁剪、掩膜 |
| 画布布局 | 1:1 等比坐标（`scaleanchor` + `constrain:domain`）、统一边距、统一色标刻度格式 |
| 图例 | 由辅助线注册表实时生成，与图层开关联动，两个工作区同一份文字结构 |
| KPI 徽章 | 分区格数 / 面积 / 有效格点 / 耗时，同一种口径与配色 |
| 探针卡片 | 点击热图 → 分区判定 + 数值；卡片结构一致，行内容按工作区取 |
| 导入导出粘贴 | 导出 JSON、导出 Markdown、复制、下载、拖放文件、粘贴文本框、剪贴板读取 |

工作区差异只体现在数据模型与可用的数据图层上：

| | 双点交会 | 知识矩阵 |
| --- | --- | --- |
| 输入 | S1 = (x, y)、θ1、ρ 模型 | Channel × Path 观测表（find / not_find / not_measure / near） |
| 后端 | `POST /api/heatmap`、`/api/probe` | `POST /api/matrix/heatmap`、`/api/matrix/probe`、`/api/matrix/import` |
| "一定测到"口径 | 按 ρ_min 判定（对 ρ 取最坏情况） | `p_det = 1`：所有正权重源点都满足 d < U(G) |
| 统计条件 | 无条件 | 可选「全部结果 / 仅测到信号」 |
| 互转 | 单 find 观测 ⇄ 知识矩阵一列 | 同左 |

## 3. 辅助线图层（注册表驱动）

矩阵工作区原来只有"可能区域"一块多边形。现在两个工作区共用同一份图层注册表
（`q2_assets/q2_app.js` 里的 `Q2.LINES`）：每条线有分组、颜色、线型、默认开关、
所需数据层与绘制器；面板、图例、绘制全部由它生成，**加一条辅助线只改一处**。

| 分组 | 图层 | 双点 | 矩阵 | 含义 |
| --- | --- | --- | --- | --- |
| 基准 | 场地圆 x²+y²=1800² | ✓ | ✓ | 场地边界 |
| 基准 | 可能源区 A | ✓ | ✓ | 双点：A1 = 楔形 ∩ D(S1,ρ)，ρ 不确定时画 ρ_min/ρ_max 两条；矩阵：全部观测约束之交 |
| 观测 | 观测点与编号 | ✓ | ✓ | 双点画 S1；矩阵画 P1…Pn，未观测列单独样式 |
| 观测 | ±1° 测向楔形与中心射线 | ✓ | ✓ | 矩阵按每个 find 观测各画一份（含射线端点到场地圆） |
| 观测 | 5 m 近距圈 | — | ✓ | near 观测的 5 m 盘、find 观测内圈 |
| 观测 | 未测到排除盘（半径 ρ_min） | — | ✓ | not_find 观测排除掉的 ρ_min 圆盘 |
| 分区 | 一定测到区 / 必然测到格点 | ✓ | ✓ | 双点给多边形边界，矩阵用格点掩膜上色 |
| 分区 | 必然无信号区 | ✓ | ✓ | 双点给 gap=0 等值线边界，矩阵用格点掩膜 |
| 分区 | 概率测得区着色 | ✓ | ✓ | 三区中的中间区 |
| 分区 | p_det 等值线 | ✓ | ✓ | 水平可调 + 可选 0.5 线 |
| 候选 | 最优格点 | ✓ | ✓ | 按当前指标在"一定测到"格点里取最优，没有则退到全部有效格点 |
| 候选 | 推荐候选 S2（局部 850, ±520） | ✓ | — | 论文里的解析最优几何 |

图层开关按工作区持久化在 `localStorage`（`q2.ui.v1`）。
面板里灰掉的图层表示**当前工作区或当前数据确实没有**这个图层（例如双点模型里没有 near 观测）。

## 4. 数据交换：JSON、Markdown、剪贴板、互转

两个工作区共用同一个"数据"小节：

* **导出 / 复制 JSON**：双点写 `q2-doublet/v1`（含 S1、θ1、ρ 模型、绘图范围、显示参数、
  以及从矩阵带来的额外观测列）；矩阵写 `q2-channel/v1`（无损保存真实观测坐标）。
* **导出 / 复制 Markdown**：两边都是项目通用的 `Channel × Path` 表，可以直接互相粘贴；
  双点的 Markdown 就是"该频道只有一个 find 观测"的一行表。
* **导入**：文本框粘贴 / 从剪贴板读取 / 拖放或选择文件（`.json .md .txt`）。
  JSON 走各自的 schema；Markdown 与旧版矩阵 JSON 交给后端的
  `normalize_matrix` 统一规范化（含角度区间 ±1° 校验、跨零处理、重复与矛盾检查）。
* **互转**：
  * 双点 → 矩阵：把 S1 变成一列 `find` 观测，带着原本从矩阵带回来的列一起过去；
  * 矩阵 → 双点：需要恰好一个 `find` 观测，多于一个时给出明确提示而不是静默取一个。

导入失败一律在面板里显示原因（例如"该知识矩阵有 2 个 find 观测，双点工作区只接受恰好 1 个"），
不会静默改状态。

## 5. 代码结构

```
script/
├── q2_page.py              统一页面与 /assets 的静态资源服务（两个蓝图共用）
├── q2_assets/
│   ├── q2_index.html       外壳标记：顶栏、收纳页、画布、探针卡片
│   ├── q2_app.css          设计令牌 + 外壳 + 全部组件样式（唯一一份样式表）
│   ├── q2_app.js           运行时：抽屉、小节、控件、图层注册表、配色、渲染、导入导出
│   ├── q2_ws_doublet.js    双点工作区：请求体与 view.layers 适配
│   └── q2_ws_matrix.js     矩阵工作区：观测表编辑、请求体与 view.layers 适配
├── q2_dashboard.py         双点端点 + 统一页面路由 + /assets
├── q2_matrix_dashboard.py  矩阵端点 + /matrix 路由（同一个页面）
└── q2_matrix_engine.py     矩阵几何与后验；额外输出 zone 与 observation_regions
```

**工作区契约**：新加一个工作区只需要 `Q2.registerWorkspace({id, label, hint, buildSections,
draw, onPlotClick, probeHint})`，并在自己的 `draw()` 里把响应整理成统一的
`view = {xs, ys, z, pdet, zone, bounds, colorbar, layers:{...}}`，然后调用
`Q2.viz.draw({view, ws, prepared, badges})`。面板、辅助线、配色、图例、探针卡片会自动复用。

关键实现细节（都踩过坑，故写进文档）：

* Plotly 只在首次 `react` 之后才把 `.on/.emit` 挂到 graph div 上，
  所以 `plotly_click` 必须在渲染之后补挂，否则点击探针静默失效；
* 辅助线面板的"可用性"依赖最近一次响应，因此每次渲染后刷新一次面板；
* 计算是异步的，切换工作区后旧工作区迟到的结果必须作废（`Q2.isActive`），否则会把上一个
  工作区的图覆盖回来；
* 画布容器不能被 flex 压缩，否则 Plotly 的固定尺寸 SVG 会溢出并盖住下方徽章与图例。
