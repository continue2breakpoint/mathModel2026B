> 对应代码：`framework/src/mathmodel2026b/knowledge.py`（矩阵本体）、

> 分支：`feat/knowledge-matrix`，基线：`main` 最后一次提交 `dbaffc2`。

## 1. 先回答：原来的算法是怎么记录知识的

旧实现（`framework/src/mathmodel2026b/state.py` 的 `ChannelState` + `strategy.py`）的知识
**不是一个结构化的台账，而是三样东西的集合**：

| 记了什么 | 存在哪 | 有什么问题 |
| --- | --- | --- |
| 每次检测的 `(检测点, 示向度)` | `ChannelState.readings: list[tuple[Point, float]]`（每频道一条链） | 只有**正例**；`no_signal` 直接丢进 trace 日志，不进入任何决策 |
| 频道所处的阶段 | `ChannelStatus`：`UNKNOWN / DETECTED / LOCALIZING / READY / CLEARED` | 只是状态机标签，**没有几何含义**，不参与"下一步去哪"的决策 |
| 探测次数 | `ChannelState.probe_count` | 唯一的"记忆"，用于兜底重扫时判断"这条频道到底扫没扫过" |

每次要用的时候，就地把读数喂给 `geometry.feasible_region()` 求交，得到一个凸多边形
（保守可行域）；可行域的最小包围圆半径 ≤ 20 m 就瞄准圆心清除。也就是说：

> **旧实现是"无状态几何"——每次决策都从原始读数重算一遍，知识只以"原始读数列表"的形式存在，
> 而且只保存正例。**

由此带来三个具体损失：

1. **负例（`no_signal`）被完全浪费。** 它其实是本题里唯一能反推"有效接收半径 R"的证据：
   在 p 点收不到，说明源到 p 的距离超过了 R。旧实现把 R 永远锁定在先验下界 1000 m，
   于是"必须覆盖到 1000m"这件事只能靠**硬编码的 7 点六边形**来保证
   （`geometry.q3_seven_point_cover_valid`），一旦想少测几个点、少走几步就没有判据了。
2. **重复检测白花钱。** "同一地点重复检测读数不变"（附录2-1）意味着同格重测信息量为 0，
   但旧实现没有任何"这一格测过没有"的索引，只能靠 `probe_count` 粗略兜底。
3. **知识不落盘、不可审计。** 事后想回答"这块区域到底看过没有"只能翻 trace 日志。

## 2. `dataType.txt` 这个设计好在哪

用户给的结构：

```
| Channel\Path | (x1, y1) | (x2, y2) | ... |
| 1 | { "status": "find",      "angle": {"lower": 2,   "upper": 4}   } | ... |
| 2 | { "status": "not find",  "angle": {"lower": 0,   "upper": 359} } | ... |
| 3 | { "status": "not clear", "angle": {"lower": 0,   "upper": 359} } | ... |
| 4 | { "status": "not measure" } | ... |
```

**行 = 频道（固定 20 行），列 = 机器狗走过的路径点（随移动增长），格 = 该点该频道的一次结论。**

我的评价：**方向完全正确，而且是本题最自然的表示**，理由有三条：

1. **频道是天然的行主键。** 附录1-1 说"每个干扰源的频道互不相同"，所以 `channel` 就是干扰源的
   唯一 ID，一行 = 一个候选目标的完整证据链。换成"位置为行"会丢掉这个一一对应。
2. **列随移动增长，但被物理分辨率限制住了。** 附录2-1 的"同点重测读数不变"意味着列宽只需
   量化到"能区分不同检测点"即可（本项目取 120 m，机器狗走 24 s），于是"这一格测过没有"
   变成 O(1) 查询 —— 这是所有剪枝的前提。
3. **正例/负例/清除失败三类结论同构。** 一个格子既能表达"看到了"，也能表达"没看到"、
   "清不动"。负例是 R 的唯一来源，没有这一列，策略就只能永远用最坏假设。

### 2.1 我做的四处修正

| 原设计 | 问题 | 修正 |
| --- | --- | --- |
| 列头写"路径点坐标" | 如果真拿**格心**去做几何，120 m 量化会把 1° 的角度误差放大到 3°+。实测某频道可行域从 7 m 被撑到 88 m，清除直接失败 | 列仍然按量化格索引（去重用），但格内额外保存**真实检测坐标** `ev.point`，一切几何只用真值 |
| `status` 只有 4 种取值 | `clear` 成功后该行怎么表示？重测会返回 `not find`，语义混淆 | 状态集扩到 6 种：`not_measure / find / not_find / near / cleared / clear_failed`，并给出与 `dataType.txt` 的**双向**映射（`CellStatus.table_text` ↔ `from_table_text`） |
| 单元格只有一个 `angle` | `not_find` 的 `angle` 填 `[0,359]` 是废信息 | 保留兼容字段，但真正的负例语义由"格内真实坐标 + 该频道当前可行域"计算得到（见 §3.2） |
| 表随移动无限增长 | 实际跑一次有 150+ 列，直接打印不可读；且"到过但没测"的格也在里面 | `as_table(cell_mode="observed")` 只保留真正观测过的列；`as_dict()` 给机读版；`limit_cols` 控制打印宽度 |

### 2.2 落地后的数据结构

```python
KnowledgeMatrix                      # channel × path 台账
├── cells: dict[channel, dict[(col,row), CellEvidence]]
├── columns: dict[(col,row), CellInfo]        # 路径列：格心、首次到达时间、访问次数
└── _stats: dict[channel, {probes, find, not_find, near, cleared, failures,
                          max_find_dist, min_not_find_dist}]   # 增量维护的派生量
```

`CellEvidence` 保存 `status / point(真实坐标) / bearing_deg / probes / last_time_s / failures`。

一句话概括这一层的作用：

> **矩阵是"索引"，几何是"答案"。** 矩阵负责回答"哪里还没看过、这个频道还缺哪块面积"，
> 连续凸几何（`geometry.feasible_region`）负责回答"源在哪"。两者分工，互不越界。

## 3. 由知识矩阵推出的三条新公式

### 3.1 有效接收半径 R 的在线夹逼（负例的唯一用途）

一个 `not_find` 观测在 p，若该点本可以测到源，则必有 `R < |p − 源|`。源位置未知但落在可行域
`P_c` 内，取可行域内离 p 最近的点做保守估计：

```
R̂ = clip( min_{p ∈ not_find} d(p, P_c),  R_min=1000,  R_max=1500 )
```

**没有负例时只能退回最坏值 1000 m** —— 这正是旧实现 7 点覆盖半径必须 ≤ 1000 m 的原因。
有了负例，`R̂` 常常被抬到 1200~1500 m，覆盖同一片区域需要的停点就少得多。
实现见 `coverage.estimate_radius`，同时记录 `radius_source` 供论文解释"凭什么敢用 1300 m"。

### 3.2 覆盖完备性证书（把"确保全部清除"变成可计算的话）

对每个未清除频道，判据是

```
∀ x ∈ P_c,  ∃ s ∈ S:  |x − s| ≤ R̂ − margin      （S = 已经测过该频道的停点集合）
```

即 `P_c` 被半径 `R̂` 的圆盘族覆盖。工程实现（`coverage.CoverageTracker`）：

* 把区域离散成 60 m 栅格，**用整数位掩码做集合运算**：
  "新增确认面积" = `(uncovered & disk).bit_count()`，上千候选 × 20 频道可在毫秒级算完；
* 一个格子算"被覆盖"要求它的**四个角**都在圆盘内（凸性保证 ⇔ 整格包含），因此判据
  对连续区域是**严格保守**的；
* `R̂` 上再留 `margin = 50 m`。

> 7 点六边形（r=1200，覆盖半径 968.9 m）与"中心 + 正七边形"（r=1110，覆盖半径 933.7 m）
> 都在这条判据下被判定为**完备**，测试见 `tests/test_knowledge_matrix.py::test_seven_point_cover_passes_certificate`。

顺带一个离线结论（`geometry.covering_radius` + 枚举同心环族）：
**在"覆盖半径 ≤1000 m"的约束下，七点六边形是最省的**（点集必须探出目标区域，
行程必然 ≥ 区域周长，所以几何本身已接近最优，继续调停点位置收益很小）。

### 3.3 频道级剪枝：这个停点还值不值得测

一个频道在停点 s 值得测，当且仅当

```
d(s, P_c) ≤ R̂_c − margin          （已收到信号的频道：停点还够得着可行域）
```

够不着就意味着这次检测**必然是 `not_find`**，纯属浪费 1 s 切换 + 5 s 检测。
在线扫描时实测能把 8 个停点的 150+ 次检测压到 129 次左右；频道被清除后该行直接退出扫描。

## 4. 决策升级：从"固定扫描表"到"证书 + 规划"

旧实现的下一个停点来自一张**硬编码的表**（7 点六边形），频道顺序固定 1→20。
新实现把决策拆成四层，每层都有明确的判据：

```
① 覆盖扫描   ：中心 + 正七边形 r=1110（覆盖半径 933.7 m，比六边形多 35 m 余量），
               每到一个停点，只测"按 §3.3 还有意义"的频道
② 精化扫描   ：把"只拿到 1 个读数、可行域最小包围圆 > 250 m"的频道**集中起来**，
               挑一个"对所有待精化频道角分离都大"的停点，一趟补完（省 n−1 趟折返）
③ 逼近清除   ：按最新估计做在线最近邻；单频道内部用解析式推进（见 §4.1）
④ 缺口补测   ：证书没过时，用**贪心集合覆盖**补停点（见 §4.2）；
               仍不过就退回确定性 7 点重扫，保证"确保全部清除"这条硬要求
```

### 4.1 逼近段的解析式（替代"估计点周围 30/60/120/250 m 同心环"）

旧实现在估计点周围的同心环上按启发式打分挑点，**初始点常在可行域边上**，第二读数与第一读数的
角分离靠运气。新实现按可行域最小包围圆半径 `ρ` 自动切换两种模式：

* **弦模式**（`ρ > 60 m`）：朝估计点一次走完剩余距离的 `1−f` 比例（默认 `f = 0.6`），
  把"走过去"和"取第二次读数"合并成一步。解析上，走到剩余距离的 `f` 倍处再读数时：

  * 角分离 ≈ `(1−f)·|PQ| / d`
  * 横向不确定度 ≈ `f·d·tan1°`，`d ≤ 1100 m` 时约 **11.5 m < 20 m**（清除判据）

* **最近点模式**（`ρ ≤ 60 m`）：直接走到可行域上离当前位置最近的点。
  "清除点与真值距离 ≤ ρ"正是 20 m 判据的来源。旧实现这一档会走过头再折回，
  白白多走 50~100 m/源。

### 4.2 缺口补测：为什么必须是"集合覆盖"而不是"面积/路程"

我第一版用的是 `新增确认面积 / 路程` 打分。它的病：**天然偏好近处的小收益**，
走到最后退化成"贴着未确认区域边缘打转" —— 实测 18 个停点之后缺口还有一半，
机器狗在离原点 1700 m 的边界带绕圈。

改成**两段式贪心集合覆盖**：

1. 候选点用三角格，间距取 `1.70·R̂`（三角格覆盖定理给出 `√3·R̂ ≈ 1.732R̂`
   是"保证覆盖"的最大间距，所以候选集合本身就是一个合法覆盖 ⇒ 一定在
   `O(面积/R̂²)` 步内把缺口清零，不会无限打转）；
2. 先选出"新增面积最大"的那一档（容忍 80% 的差距），再在这一档里挑**离当前位置最近**的。

也就是"先保证盖得住，再保证走得近"，两个目标分开处理，比揉进一个线性打分稳得多。

## 5. 问题4：定向源让"负例"失效，怎么办

定向源的覆盖角只有 ±90°，于是"在某点收不到"有**两个互斥解释**：距离超出 R，
**或者**该点落到了锥的背面。这带来一个致命盲区：

> 某个位置只被 1~2 个停点"够得着"，而这几个停点又都在锥的背面时，
> 在这几个停点上无论怎么扫都发现不了它。

### 5.1 锥一致性判据（`coverage.invisible_mask`）

锥朝向 u 未知，但正例 apex 是"必须被看到"的方向。对负例点 p，要求

```
|S − p| > R_min     （距离原因，与朝向无关）
或  ∠( dir(S→p), dir(S→apex) ) > 90°  对**所有**正例 apex 成立
```

只要存在一个 apex 与 p 同向（点积 ≥ 0），就要求 u 同时满足"≥90°"和"≤90°"，
自相矛盾 ⇒ S 处不可能是源，可以从待确认区域里删掉。剩下的就是**锥盲区**，
补测停点只需要覆盖它，而不是重扫整个 1800 m 圆域。

**没有正例时这条判据完全失效**（一个定向源总可以把锥背对任意有限个停点），
所以实现里 `finds` 为空直接返回全区域。这也解释了为什么定向场景的清除率天花板更低：
负例在这个场景下信息量近乎为零。

### 5.2 负例圆盘排除在定向场景必须关掉

全向情形下 `not_find` 直接给出"源不在该点 R 圆盘内"。定向情形下这么做是**错的** ——
反方向的 `not_find` 可能只是锥没照到。实测把这条沿用下来，清除率从 100% 掉到
**3/11 = 27%**（与旧实现 30/30 只清 9 个的现象完全一致）。
现在 `_not_find_exclusion(directional=True)` 直接返回 0，交给 §5.1 的锥判据。

## 8. 已知局限与下一步

1. **缺口补测的收益还没吃满**：证书判"不完备"时，`plan_cover` 会补停点，
   但补测的目标区域（锥盲区）在定向场景下经常是"整片 − 残余"，收益有限。
   更狠的做法是把覆盖率做成**多假设 POMDP**（对"该位置有没有源"维护假设集合，
   用信息增益而非面积做目标函数）。
2. **精化扫描的停点选择是 max-min 近似**，没有考虑"该停点对某个频道其实够不着"
   以外的约束（比如已清除频道的行进代价）。可以用一个小规模贪心替换。
3. **未做 Replay 一致性验证**：`client.ReplayClient` 能把线上演练的 `run.jsonl` 重放，
   正式测试前应当跑一遍，确认矩阵/证书在真实接口时序下同样成立。
4. **Q3 的 +10% 时间**应该继续压：优先目标是 `refine_sweep` 的触发条件
   （现在阈值 250 m 可能偏松）与横向补测的半径选择。
